## Suspected defects

1. **D1 (FIXED 2026-11-01; confirmed live by SYNC-030 on both platforms) — `rbx ps` could never open the Studio push review.** `automation_push_args` sets `args.yes = true` for every daemon push and `no_review = !reviewed`; the review is requested only when `!no_review && !yes && !global_yes()`. So the guide ("a push of more than 5 changes opens a review panel"), the `--yes` help text, and `rbx rv` apply only to direct editor mutations (`apply_editor_change_with_warm_bridge`). Protected-write review is likewise short-circuited. SYNC-030 decides: either the review opens or the docs and flags are stale. Since Aug 13 (8a978b2).
2. **D2 — stale local-file digest turns an unsaved close into a silent file revert.** `PairRecord.local_file_digest` is refreshed only in `Coordinator::prepare` (lon/lst/restore). Sequence: lon; sync to v2; save in Studio (Ctrl+S, no close); sync to v3; close unsaved; reopen; `lst`. The digest differs from the record, `should_bootstrap_studio_from_editor` is false; with reconcile priority the files (v3 == baseline) are "unchanged" and Studio (v2) is "changed" → files written back to v2 (history entry, no warning). Correct: treat an unchanged-since-last-sync Studio file as a bootstrap or at least a conflict. Fix idea: refresh the digest whenever the record is written during a sync, or compare the file mtime against the last sync time.
3. **D3 — `ps --verify` and `drop_unchanged_source_changes` still read the editor document.** `getLiveSourceBatch` uses `readSource` (GetEditorSource first); with a tab restored on reopen lagging the property, `ps --verify` reports a mismatch while the Source equals the file. 9912d13 fixed only the write verification.
