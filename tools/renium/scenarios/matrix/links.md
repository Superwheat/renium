# Renium links, packages, plugins and collaboration situation matrix

Enumerated 2026-11-01 from the code, the guides (links.md, projects.md, plugins.md) and the incidents in memory. Every row names the state to construct, the action, what must hold, and the code path or incident proving the situation occurs. Legend: size small = baseplate fixture; heavy = sync.md H10 (renium-push-repro copy with ReplicatedStorage.TopbarPlus, a package owned by group HD Admin). "no Studio" rows keep Studio closed (`needs_studio=False`); "Win only" rows cannot run on macOS. "Covered" names an existing unit test, "none" means only the code path exists; "runner X" names the scenario with id X in scenarios/areas/links.py (LINK) or areas/plugins.py (PLUG) that scripts the row (one scenario may cover several rows), "excluded: ..." a row the runner cannot run here. Actions run with `--output-mode json` (the runner adds it); field names are the result's JSON keys. `RS[A,B]` stands for `--service ReplicatedStorage --path '["ReplicatedStorage","A","B"]'`. Path prefixes: `plk/` = src/project/package_links, `plg/` = src/plugins, `col/` = src/collab, `sdk/` = tools/renium-plugin-sdk/src; other paths are under tools/renium/src. Push protection of read-only links and foreign packages is sync.md SYNC-040..046, not repeated. The owner's Roblox account is moderated, so package publish, cloud package update, Creator Store, Open Cloud and owned-package success paths are covered only on their refusal or offline side. Helpers (L0–L7, P1–P2, C1–C2) are at the end.
