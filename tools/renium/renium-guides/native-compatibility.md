# Native compatibility

Studio updates do not disable native features by version. `rbx native-probe --pid PID` performs read-only structural checks and prints one verdict per operation. `--require-native` exits unsuccessfully if any operation is degraded. `rbx status` and `rbx dr` include the selected process's cached verdicts and reasons. A passing probe validates locators; it does not claim a runtime stress test passed.

A failed operation uses its available plugin path. Source verification remains available. Protected values without a lossless bridge path remain pending with a precise error. Optional voxel-history acceleration can be degraded while ordinary history recording and explicit Terrain rollback work.

Windows playtest discovery: `rbx native-probe --pid 1234 --playtest-discovery` prints structured evidence for reflection dispatch, test arguments, Play/Stop/controller strings, RTTI/vtables, identity/service request code and StartServer/StartClient task inputs. It only reads the selected process and executable; it cannot launch Studio, load helpers or invoke engine methods. No raw command line, live file path, window title or join-ticket value is returned. Code strings are executable constants.

Add `--playtest-http` for a focused teleport HTTP, join/placelauncher, response-parser and asset-delivery catalog. It seeds TeleportService member bindings and transport IAT references, and reports loaded module names/bases and unresolved response contracts. Explicit `--playtest-anchor` filters replace that catalog; explicit RVAs select the graph roots. This remains read-only discovery: it captures no request bodies and performs no interception. An HTTP request's native callback and a local destination session must be proven separately.

The report includes unresolved evidence and graph truncation/frontier RVAs. Use `--playtest-rva 0x1234 --playtest-depth 2 --playtest-max-functions 512` to expand a reported function, `--playtest-anchor TEXT` to select string/RTTI anchors instead of the default catalog, or `--playtest-object 0x1234` to inspect a reported live object's RTTI and code-referenced object pointers. Addresses are observations for that process/build, never production offsets. `ok` means collection succeeded; discovery's `nativeSwitchReady` remains false and `--require-native` always fails after printing that report. The Windows executor separately qualifies its launch, dispatch, loader and join-data contracts against the running image before installing scoped hooks. These optional playTeleport operations appear in daemon status when requested and do not alter the canary's required operations. See `RENIUM/teleport.md` for supported workflows.

Maintainers: `powershell -File tools/renium/tests/native-canary.ps1` downloads the current WindowsStudio64 deployment into a unique scratch directory, launches its scratch place without taking focus, probes it and writes a per-operation table. It stops only its own scratch window and leaves evidence. Use `-Studio PATH -Place FILE` to compare an installed build. The scheduled **Studio native canary** workflow runs on `self-hosted, Windows, X64` and fails visibly for degraded operations.

When a probe fails, retain `probes.json` and the deployment manifest; compare executable code/RTTI and update the narrow locator in `src/studio/native/serializer`. Add a relocated-layout regression and rerun probes plus the affected operation on a scratch place, including reconnects. Never extend a build allowlist or relax allocator/ownership checks to make a probe pass. macOS uses the same verdict model. Its DataModel queue and package operations currently report degraded because their former fixed-field locators lack structural proof; snapshot and OS capabilities are checked separately. Windows CI does not verify macOS runtime behavior.
